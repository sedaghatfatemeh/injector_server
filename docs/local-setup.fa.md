# راهنمای اجرای پروژه روی ویندوز

این راهنما برای اجرای محلی پروژه در PowerShell است. بک‌اند Django و دیتابیس PostgreSQL با Docker اجرا می‌شوند و فرانت‌اند React/Vite با npm اجرا می‌شود. برای این روش نیازی به نصب جداگانه Python یا PostgreSQL روی ویندوز نیست.

## ۱. پیش‌نیازها

Docker Desktop را با پشتیبانی از Linux containers نصب و اجرا کنید. Node.js و npm نیز باید نصب باشند؛ نسخه Node.js باید با نسخه Vite ثبت‌شده در `package-lock.json` سازگار باشد.

در ترمینال VS Code این دستورها را بررسی کنید:

```powershell
docker --version
docker compose version
node --version
npm.cmd --version
```

دریافت اولیه imageها و وابستگی‌ها به اینترنت نیاز دارد.

## ۲. آماده‌سازی تنظیمات

وارد ریشه پروژه شوید؛ همه دستورهای Docker و npm این راهنما از همین پوشه اجرا می‌شوند:

```powershell
cd C:\Users\Sedaghat\injector_server
```

اگر پروژه را در مسیر دیگری قرار داده‌اید، مسیر بالا را تغییر دهید.

فقط اگر فایل `.env` وجود ندارد، آن را از نمونه بسازید؛ فایل موجود بازنویسی نمی‌شود:

```powershell
if (-not (Test-Path .env)) {
    Copy-Item .env.example .env
}
```

فایل `.env` در ریشه پروژه را در ویرایشگر باز کنید. مقادیر زیر را بررسی کنید و دو مقدار نمونه مربوط به secret و رمز را با مقادیر خصوصی خودتان جایگزین کنید:

```dotenv
DJANGO_SECRET_KEY=replace-with-your-own-long-random-secret
DJANGO_DEBUG=true
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1
POSTGRES_DB=injector_server
POSTGRES_USER=injector_server
POSTGRES_PASSWORD=replace-with-your-own-local-database-password
POSTGRES_PORT=5432
```

سایر تنظیمات نمونه را نگه دارید. فایل `.env` حاوی اطلاعات محرمانه است و نباید در Git ثبت شود. Compose همین فایل ریشه را می‌خواند؛ برای این روش نیازی به ساخت `backend/.env` یا export کردن دستی متغیرها نیست.

## ۳. اجرای دیتابیس و بک‌اند

دستورها را به ترتیب اجرا کنید و فقط پس از موفقیت هر مرحله ادامه دهید:

```powershell
docker compose build api
docker compose up -d db
docker compose run --rm api python manage.py migrate
docker compose up -d api
```

دستور `migrate` جدول‌های دیتابیس را ایجاد یا به‌روز می‌کند. پیش از اجرای نسخه‌ای که migration جدید دارد، آن را دوباره اجرا کنید.

وضعیت سرویس‌ها را ببینید:

```powershell
docker compose ps
```

سرویس `db` باید سالم (`healthy`) و سرویس `api` در حال اجرا باشد. آدرس زیر را در مرورگر باز کنید تا آمادگی بک‌اند و اتصال دیتابیس بررسی شود:

<http://localhost:8000/health/ready/>

## ۴. ساخت اولین حساب مدیر

در راه‌اندازی اولیه اجرا کنید:

```powershell
docker compose exec api python manage.py createsuperuser
```

نام کاربری، ایمیل و رمز عبور را طبق پرسش‌های ترمینال وارد کنید. برای ورود به داشبورد، **ایمیل و رمز عبور** استفاده می‌شود؛ ایمیل را خالی نگذارید و از ایمیل یکتا استفاده کنید. هنگام تایپ رمز عبور چیزی نمایش داده نمی‌شود.

پنل مدیریت Django در آدرس زیر در دسترس است:

<http://localhost:8000/admin/>

فایل‌های CSS و JavaScript پنل مدیریت با WhiteNoise از مسیر `/static/` سرو می‌شوند. اگر پنل بدون استایل نمایش داده شد، پس از دریافت تغییرات، image و سرویس API را بازسازی کنید:

```powershell
docker compose build api
docker compose run --rm api python manage.py migrate
docker compose up -d --no-deps api
```

سپس با `Ctrl+Shift+R` صفحه را بازخوانی کنید. آدرس `http://localhost:8000/static/admin/css/base.css` باید فایل CSS را نمایش دهد. اجرای `collectstatic` به‌تنهایی جایگزین سرو فایل‌های استاتیک نیست؛ این مرحله هنگام ساخت image انجام می‌شود.

پس از ورود به داشبورد با حساب مدیر، از بخش **کاربران** حساب کارکنان را ایجاد کنید. نقش پشتیبانی دسترسی مشاهده دارد و مدیریت کاربران مخصوص مدیر ارشد است. ثبت‌نام عمومی و ورود مشتری در MVP وجود ندارد.

## ۵. اجرای فرانت‌اند

برای دستورهای ساخت و تست خودکار رابط کاربری، [راهنمای بررسی فرانت‌اند](frontend-verification.md) را ببینید. تست مرورگر روی پورت جداگانهٔ ۵۱۷۴ اجرا می‌شود و داده‌های واقعی دیتابیس را تغییر نمی‌دهد.

یک ترمینال جدید در VS Code باز کنید و اجرا کنید:

```powershell
cd C:\Users\Sedaghat\injector_server
npm.cmd ci
npm.cmd run dev
```

این ترمینال را باز نگه دارید و داشبورد را در آدرس زیر باز کنید:

<http://localhost:5173>

با ایمیل و رمز حساب مدیر وارد شوید. تنظیمات `vite.config.js` درخواست‌های `/api` و `/health` را به بک‌اند روی پورت ۸۰۰۰ هدایت می‌کند؛ در اجرای معمولی نیازی به تنظیم دستی آدرس API نیست. برای هماهنگی با تنظیمات ورود، از همین آدرس `localhost:5173` استفاده کنید.

داشبورد به‌صورت پیش‌فرض به دیتابیس واقعی محلی متصل است و در شروع ممکن است خالی باشد. برای این حالت `VITE_DEMO_MODE` نباید `true` باشد. نمونه مستقل `prototype/onboarding/` داده‌های نمایشی دارد و به بک‌اند متصل نیست.

## ۶. اجرای دفعات بعد

Docker Desktop را اجرا کنید، سپس در ریشه پروژه دستورهای زیر را بزنید:

```powershell
docker compose up -d db api
npm.cmd run dev
```

نیازی به ساخت مجدد حساب مدیر یا نصب دوباره وابستگی‌ها در هر اجرا نیست. پس از تغییر وابستگی‌های فرانت‌اند، `npm.cmd ci` را دوباره اجرا کنید. پس از تغییر کد یا وابستگی‌های بک‌اند، برای به‌روزرسانی image و اعمال migrationها اجرا کنید:

```powershell
docker compose build api
docker compose run --rm api python manage.py migrate
docker compose up -d api
```

پس از تغییر `.env`، برای اعمال تنظیمات جدید بک‌اند اجرا کنید:

```powershell
docker compose up -d --force-recreate api
```

## ۷. توقف پروژه

برای توقف فرانت‌اند، در ترمینال آن `Ctrl+C` بزنید. برای توقف بک‌اند و دیتابیس:

```powershell
docker compose stop
```

اطلاعات دیتابیس در volume ذخیره می‌شود و با این دستور باقی می‌ماند. از `docker compose down -v` برای توقف روزمره استفاده نکنید؛ گزینه `-v` داده‌های volume دیتابیس را حذف می‌کند.

## رفع خطاهای رایج

- **Docker در دسترس نیست:** Docker Desktop را اجرا کنید و صبر کنید موتور Docker آماده شود.
- **بک‌اند بالا نمی‌آید یا health آماده نیست:** لاگ‌ها را با دستور زیر ببینید و بررسی کنید مرحله `migrate` موفق بوده باشد:

  ```powershell
  docker compose logs --tail=100 api db
  ```

- **رمز PostgreSQL رد می‌شود (`password authentication failed`):** تغییر `POSTGRES_PASSWORD` در `.env` رمز یک دیتابیس قبلاً ساخته‌شده را تغییر نمی‌دهد. این خطا مربوط به اتصال Django به دیتابیس است و با تغییر رمز حساب مدیر داشبورد رفع نمی‌شود. اگر رمز فعلی دیتابیس را دارید، آن را در `.env` قرار دهید و سرویس API را دوباره بسازید. در محیط محلی Docker این پروژه، اگر می‌خواهید رمز نقش دیتابیس را با مقدار جدید `.env` هماهنگ کنید، از اتصال داخلی کانتینر استفاده کنید:

  ```powershell
  docker compose exec db psql -U injector_server -d injector_server
  ```

  اگر `POSTGRES_USER` یا `POSTGRES_DB` متفاوت است، نام‌های بالا را متناسب با دیتابیس موجود تغییر دهید. سپس داخل `psql` اجرا کنید:

  ```text
  \password injector_server
  ```

  رمز فعلی `POSTGRES_PASSWORD` در فایل ریشه `.env` را دو بار در اعلان رمز وارد کنید؛ رمز را داخل دستور SQL یا تاریخچه ترمینال ننویسید. با `\q` خارج شوید و در PowerShell اجرا کنید:

  ```powershell
  docker compose up -d --force-recreate api
  docker compose exec api python manage.py migrate --check
  ```

  سپس <http://localhost:8000/health/ready/> را بررسی کنید و ورود را دوباره انجام دهید. اگر اتصال داخلی هم مجاز نیست، از مدیر دیتابیس کمک بگیرید. volume را برای رفع این خطا حذف نکنید؛ این روش حساب‌ها و داده‌های موجود را نگه می‌دارد.
- **پورت ۸۰۰۰ یا ۵۱۷۳ اشغال است:** اجرای قبلی پروژه یا برنامه‌ای را که از آن پورت استفاده می‌کند متوقف کنید. Vite در این پروژه به پورت ۵۱۷۳ مقید است.
- **ورود ناموفق است:** از ایمیل حساب ساخته‌شده استفاده کنید و از روشن بودن بک‌اند مطمئن شوید. ورودهای مکرر ناموفق ممکن است موقتاً با محدودیت نرخ مواجه شوند.
- **خطای اجرای اسکریپت npm در PowerShell:** دستورهای همین راهنما را با `npm.cmd` اجرا کنید.

برای اتصال pgAdmin، اجرای بومی Python و تست‌های PostgreSQL، [راهنمای بک‌اند](../backend/README.md) را ببینید. [گردش کار توسعه](development-workflow.md) مربوط به مدیریت وظایف با Beads است؛ Beads پیش‌نیاز اجرای برنامه نیست. این دستورها برای محیط توسعه محلی هستند؛ پیش‌نیازهای انتشار عملیاتی در [README پروژه](../README.md#production-prerequisites) آمده است.

## ورود مشتری و پنل اختصاصی

اگر پروژه از قبل اجرا می‌شود، پیش از ارتقا از دیتابیس نسخه پشتیبان بگیرید. برای اضافه‌شدن جدول عضویت مشتری، از ریشه پروژه اجرا کنید:

```powershell
docker compose build api
docker compose run --rm api python manage.py migrate
docker compose up -d api
```

این ارتقا با migration شماره `0006_customer_membership` انجام می‌شود؛ حساب‌ها و دستگاه‌های قبلی را تبدیل یا حذف نمی‌کند. ایمیل تماس سازمان به‌صورت خودکار حساب ورود نمی‌سازد. برای اجرای frontend نیز دستور معمول `npm.cmd run dev` را اجرا کنید؛ اگر از قبل اجراست، صفحه را بازخوانی کنید.

۱. با حساب مدیر کل وارد سامانه شوید و سازمان مشتری را در بخش **مشتریان** ثبت کنید.
۲. دستگاه را در بخش **دستگاه‌ها** به همان سازمان اختصاص دهید.
۳. بخش **حساب‌های مشتریان** را باز کنید و **افزودن حساب مشتری** را بزنید. ایمیل و گذرواژهٔ اولیه را وارد و سازمان فعال را انتخاب کنید. برای سازمان‌های بیشتر از یک صفحه، جست‌وجو یا صفحه‌بندی فرم را استفاده کنید.
۴. گذرواژهٔ اولیه را از مسیر امن به مشتری تحویل دهید؛ سامانه آن را دوباره نمایش نمی‌دهد یا خودکار ایمیل نمی‌کند.
۵. مشتری از همان صفحه **ورود به سامانه** با ایمیل و گذرواژه وارد می‌شود و به مسیر `/customer/devices` می‌رود. در **دستگاه‌های من** فقط دستگاه‌های سازمان خودش، جزئیات فقط‌خواندنی، آخرین ارتباط و وضعیت تخمینی اتصال را می‌بیند.

هر حساب مشتری فقط یک سازمان دارد؛ یک سازمان می‌تواند چند حساب داشته باشد. مشتری نباید `is_staff`، `is_superuser` یا گروه `support` داشته باشد. ثبت‌نام عمومی، مدیریت کاربران یا دستگاه‌ها، گزارش رویدادها، انتشار نسخه و کنترل دستگاه برای مشتری فعال نیست. حساب مشتری را از رابط برنامه بسازید، نه فرم ساخت کارکنان در Django admin.

مدیر کل در فهرست حساب‌های مشتریان می‌تواند حساب را غیرفعال کند. دسترسی نشست قبلی در درخواست بعدی رد می‌شود. بایگانی سازمان یا حذف عضویت نیز دسترسی پنل را می‌بندد؛ جابه‌جایی دستگاه، دسترسی سازمان قبلی به آن دستگاه را در درخواست بعدی حذف می‌کند. این کارها آزمون دستگاه یا ارتباط خود دستگاه با سرور را متوقف نمی‌کنند.

«وضعیت اتصال» تخمینی بر اساس آخرین ارتباط موفق است؛ آستانهٔ پیش‌فرض ۱۵ دقیقه با `DEVICE_ONLINE_WINDOW_MINUTES` تغییر می‌کند. دستگاهی که هنوز ارتباطی نداشته، پیام مخصوص دارد. این پنل دکمه‌ای برای برقراری اتصال یا کنترل آزمون ندارد. وضعیت در بازخوانی، بازگشت به پنجره و هر ۶۰ ثانیه در صفحهٔ قابل‌مشاهده بررسی می‌شود.

تنظیمات موجود `STAFF_SESSION_AGE_SECONDS` و `STAFF_LOGIN_RATE` برای ورود کارکنان و مشتریان مشترک‌اند. انقضای نشست، خروج و تغییر رمز، دسترسی نشست را محدود می‌کنند. برای تست رابط مشتری، حالت نمونه `VITE_DEMO_MODE` باید خاموش باشد؛ پنل زنده از دادهٔ نمونه استفاده نمی‌کند.
